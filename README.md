# AR-паспорт оборудования (ЛР №4)

Веб-страница на A-Frame + AR.js. Камера распознаёт маркер, и над ним появляются 3D-модель оборудования, цветной индикатор состояния и карточка с данными.

## Состав проекта

| Файл | Назначение |
|---|---|
| `index.html` | AR-сцена и логика страницы |
| `machines.json` | данные об оборудовании (меняются без правки кода) |
| `markers/*.patt` | шаблоны маркеров для AR.js |
| `markers/*.png` | изображения маркеров |
| `markers_print.pdf` | лист A4 для печати, сторона маркера 60 мм |
| `make_markers.py` | генерирует `.patt`, `.png` и `markers_print.pdf` |

## Запуск в VS Code на компьютере

Двойной щелчок по `index.html` не подойдёт: браузер не загрузит `machines.json` и маркеры с адреса `file://`. Страницу нужно открыть через локальный сервер.

1. Распакуйте архив и откройте в VS Code папку `ar-lab4` (File → Open Folder).
2. VS Code предложит установить рекомендуемые расширения, нажмите **Install**. Если не предложил, установите **Live Server** (автор Ritwick Dey) через Extensions.
3. Щёлкните правой кнопкой по `index.html` → **Open with Live Server** (или кнопка **Go Live** справа внизу).
4. Откроется `http://127.0.0.1:5500/index.html`. Разрешите доступ к камере.
5. Покажите веб-камере маркер: распечатанный `markers_print.pdf` или `markers/lathe.png`, открытый на экране телефона.

Для `localhost` браузер разрешает камеру без HTTPS, поэтому на компьютере этого достаточно. Нужен интернет, потому что A-Frame и AR.js подключаются с jsDelivr.

## Запуск на смартфоне

Телефону камеру дадут только по **HTTPS**. Простых способов два.

**Способ 1: проброс порта в VS Code (быстро, для проверки)**
1. Запустите Live Server, как описано выше.
2. Внизу VS Code откройте вкладку **Ports** (или View → Open View → Ports).
3. **Forward a Port** → введите `5500` → войдите через GitHub, если попросит.
4. Правой кнопкой по строке порта → **Port Visibility → Public**.
5. Откройте на телефоне выданный адрес `https://…devtunnels.ms/index.html`. На странице-предупреждении нажмите **Continue**, затем разрешите камеру.

**Способ 2: GitHub Pages (постоянный адрес для отчёта)**
1. Создайте публичный репозиторий на GitHub и загрузите туда содержимое папки `ar-lab4`.
2. Settings → Pages → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)` → Save.
3. Через 1–2 минуты страница будет доступна по адресу `https://<логин>.github.io/<репозиторий>/`.

Маркеры печатайте в масштабе 100% (без «подогнать по размеру»), белое поле вокруг чёрной рамки не обрезайте.

## Пересоздание маркеров (необязательно)

Готовые маркеры уже лежат в архиве. Скрипт нужен, только если вы меняете узоры или подписи.

```bash
pip install -r requirements.txt
python make_markers.py
```

Скрипт выводит похожесть маркеров друг на друга и на свои повороты. Чем ниже значение, тем лучше; сейчас оно около 0,3.

## Изменение данных

Отредактируйте `machines.json` и обновите страницу. Даты пишутся в формате `ГГГГ-ММ-ДД`. Состояние вычисляется само:
- `"repair": true` → «На ремонте», красный;
- дата `nextTO` уже прошла → «Требуется ТО», оранжевый;
- иначе → «Исправен», зелёный.

## Если не работает

| Симптом | Причина |
|---|---|
| Вверху «Не удалось загрузить machines.json» | страница открыта как файл, запустите через Live Server |
| Чёрный экран, камера не включается | не дано разрешение на камеру, или на телефоне открыт адрес без `https` |
| Белый экран, ничего не грузится | нет интернета (библиотеки идут с CDN) |
| Маркер не распознаётся | маркер слишком мелкий или бликует, белое поле обрезано, мало света |
